# Memory editing and study generation recovery

Memory settings use a native modal with explicit textarea autofocus, visible insertion caret and focus outline, editable text selection, Escape handling and cleanup that restores focus. An empty field keeps Save memory disabled; the example is a placeholder rather than a saved preference. Automated DOM checks cover typing, saving and closing. Native Chromium checks also click, type, save and close with Escape at 390, 1280 and 2560 pixels. Focus is applied after showModal and restored after cleanup; the mobile account menu stays on-screen. The affected user browser still needs a check after updating.

The topic-count capacity endpoint is retained for compatibility, but its heuristic no longer truncates the requested number. The frontend no longer presents its estimate as a number of questions the material can support. Existing per-request size limits and account/global token allowances remain; these are resource controls, not claims about the number of possible questions.

Assessments are generated in batches of five, flashcards in batches of ten. Allocation prompts vary learning objectives; refills rotate source topics and question angles while preserving missing question types and supported numerical sources. Generation can run for up to twelve rounds, stopping earlier when the requested count is reached or three consecutive rounds add no valid items. Cancellation and existing budgets still apply. Prompts explicitly describe conditional requirements such as four to six options and exactly one correct option for multiple choice. Schema, citation identity, source support and duplicate checks are retained. Saved partial results remain available and have one shortfall notice.

This does not guarantee every document can yield any requested count or that a model always follows its schema. The user's EventHandling.pdf is not available for a live reproduction. Tests exercise controlled fixtures, not hosted model accuracy.

Update an existing local installation with `git pull origin main`, then `powershell -ExecutionPolicy Bypass -File judge/enable-code.ps1` if Code & data is enabled. The dependency manifests and Dockerfile are unchanged by this patch so completed dependency layers can be reused. Refresh the page, test memory input, and create a new assessment; previously saved nine-question assessments are preserved.

Browser regression: install test-only Playwright externally, set `AURA_UI_TEST_MODULES` to that node_modules directory (and `AURA_LAYOUT_CHROMIUM` when using a custom Chromium), then run `node scripts/check_memory_browser.mjs http://127.0.0.1:4173` against a Vite preview built with `VITE_API_BASE_URL=/api`. The browser intercepts only authored fixture API responses. No production account, uploaded document or provider request is used.
